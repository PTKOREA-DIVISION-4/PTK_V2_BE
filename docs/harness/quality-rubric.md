> 범위: **BE 전용**. 태그는 `README.md` 참고.
> **[U 2026-11-27]** 샘플 PDF 와 비교해 "샘플 정도의 결과물이 나오도록 **자체 평가 기준을 세워 개선하는 루프**"를 돈다. **[A 2026-11-27]** 목표는 **90점 이상**이다.

## 1. 실행

```bash
python scripts/evaluate_factbook.py --project-id <프로젝트ID> --pptx <내보낸.pptx 경로> --api http://127.0.0.1:8000/api/v1
```

필요 조건: 백엔드 서버 실행 중, 대상 프로젝트에 장표 초안이 생성돼 있고 PPTX 가 내보내져 있을 것. 출력은 총점·영역별 점수·감점 사유(JSON)다.

## 4. 알려진 한계 — v1 점수를 곧바로 "샘플 동등"으로 해석하지 말 것

- **페이지 깊이·정보 밀도를 채점하지 않는다.** 구조 점검 기준이 본문 22장이다. 내부 기준 샘플(56장, 간지·목차 포함) 대비 생성 결과는 23장(표지 + 본문 22)이라, v1 이 95.4 점이어도 **분량·밀도는 기준 샘플에 크게 못 미친다** (사용자 지적 2026-11-27).
- **시각 요소 비율**(차트·표·이미지를 가진 슬라이드의 비율)과 **슬라이드당 정보량**을 측정하지 않는다.
- 3번 영역의 음수 부호 보존 검사는 DataLab 시계열의 음수 성장률 데이터를 기반으로 동적 판별하며, 모든 항목이 휴리스틱(문자열·개수 검사)이라 문장의 사실 정확성을 검증하지는 않는다. 사실 확인은 `확인 못 함` 원칙과 출처 연결(`project-rules.md` BE-4, BE-17)로 관리한다.
- v2(기준 샘플 대비 섹션별 페이지 깊이·정보 밀도·시각 요소 비율·경쟁사/보도/트렌드 실데이터 커버리지 반영)는 **사용자의 진행 방향 확정 후** 별도 이슈로 만든다. 그 전까지 루브릭 점수를 올리기 위해 기준을 완화하지 않는다.
