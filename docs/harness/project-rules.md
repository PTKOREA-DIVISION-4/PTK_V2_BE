# 프로젝트 규칙 — PTK_V2_BE

> 범위: **BE 전용**. 출처 태그(`[U]` `[A]` `[D]`)는 `README.md` 참고. 날짜는 사용자가 해당 지시를 한 대화 시점이다.
> 이 문서의 `[U]` 항목은 대화 원문에 근거가 있는 것만 적었다. 근거가 약한 내용은 `[D]` 로 표시했다.

## 1. 제품 원칙

- **BE-1 [U 2026-11-25]** 팩트북은 **단일 브랜드 · 단일 제품(또는 주력 라인) 단위**로 실행한다.
- **BE-2 [U 2026-11-25]** **산업군 특성**에 따라 수집·분석을 분기한다: *리뷰·실사용 후기 중심* vs *일반 마케팅·시장 지표 중심*.
- **BE-3 [U 2026-11-25]** 본문 순서는 **0. 분석 개요 → 1. 자사 분석 → 2. 시장 분석 → 3. 경쟁사 분석 → 4. 소비자 분석 → 5. 현황 요약 및 결론·과제 방향(AS-IS → TO-BE)** 이다. 5. 현황 요약(Summary)은 내용이 많을 때 **1장으로 압축하지 않고 2장 또는 4장으로 분할**한다. 사용자는 "이 목차만 잘 지키면 된다"고 했다.
- **BE-4 [U 2026-11-25]** 불필요한 **중복·외부 발췌 의존** 항목을 제거하고, **출처와 근거 문장을 연결**한다.
- **BE-5 [U 2026-11-25]** **숫자 인포그래픽 영역을 분리**해 구성하고, 이해를 돕는 **예제 설명 이미지·참조 이미지 배치 규칙**을 둔다.
- **BE-6 [U 2026-11-27]** 결과물 수준의 기준은 **샘플 PDF**다. 같은 케이스로 팩트북을 생성하면서 그 수준이 나오도록 테스트·수정을 반복한다.
- **BE-7 [U 2026-11-27]** PPTX 의 디자인 포맷은 **웹 UI(Division 4)와 동일하게 일정**해야 한다. (색·아이콘 규칙은 FE 레포 `design-tokens.md`)

- **BE-9 [U 2026-11-25]** API 키는 **백엔드 환경변수로 안전하게 관리**한다. (상세 금지 규칙은 `ai-operating-protocol.md` P-11)

## 3. 안정성·UX 방어 (BE 가 책임지는 부분)

- **BE-10 [U 2026-11-25]** 네트워크·요청이 불안정해도 **버튼 무반응, 오류, 빈 장표, 2장짜리 초안 출력** 같은 치명적 버그가 나지 않게 **상태 관리와 명시적 피드백**을 제공하고, **출력 전 사전 검증(QC)** 로직을 둔다.
- **BE-11 [D]** 위 요구의 BE 구현은 `Pre-flight QC Gate`(`services/qc_service.py`)이며, QC 가 `BLOCKER` 면 PPTX 를 만들지 않는다. 비동기 작업 생성 API 는 `Idempotency-Key` 로 중복 실행을 막는다 (`docs/API_SPEC.md` §1.1).

## 4. 개발 방식

- **BE-12 [U 2026-11-25]** DB 는 **MySQL** 이다. **백엔드를 먼저 구축**하고, **API 명세서가 나오면 그에 맞춰 프런트 UI/UX 를 설계**한다.
- **BE-13 [D]** 따라서 API 를 바꾸는 PR 은 `docs/API_SPEC.md` 와 `docs/openapi.json` 을 **같은 PR 에서** 갱신한다 (FE 설계 기준서이므로).
- **BE-14 [U 2026-11-27 / 2026-11-28]** **개발 과정(트러블슈팅 · 문제점 · 문제 원인 · 해결 과정)을 기록**하되, 실제 고객사명·실측치가 포함된 일지는 **로컬에만 보관(PUBLIC 레포 커밋 금지)** 하고, 레포에 남길 기술 메모가 필요할 때는 100% 익명화된 내용만 올린다.
- **BE-15 [U 2026-11-27]** 샘플과의 비교로 **자체 평가 기준을 세워 개선 루프**를 돌린다. **[A 2026-11-27]** 기준은 `quality-rubric.md` 의 100점 루브릭이며 **목표는 90점 이상**이다. (한계와 알려진 문제는 같은 문서 §4)
- **BE-16 [U 2026-11-27]** 백엔드 로직이 **지저분해지지 않게** 하고 **더 좋은 방향이 있는지 항상 먼저 생각**한다 (`ai-operating-protocol.md` P-9b).

## 5. 데이터 무결성 [A 2026-11-27]

- **BE-17 [A 2026-11-27]** **수집하지 못한 수치는 지어내지 않고 `확인 못 함`** 으로 표기한다 (환각 0 원칙). 허용 표기는 `확인 못 함` 하나이며, `확인 중` · `추후 보강` · `TODO` · `TBD` · `Lorem` 같은 임시 문구는 산출물에 남기지 않는다 [D].
- **BE-18 [A 2026-11-27]** 하락·감소 수치의 **마이너스(`-`) 부호를 지우지 않는다** (예: `-12.5%`). 문장 정리 함수(`clean_slide_text`)는 불릿 기호만 제거하고 음수 부호는 보존해야 한다 [D].
- **BE-19 [A 2026-11-27]** 변경 후 `PYTHONPATH=. pytest -v` 가 통과해야 한다 (`verification.md`).

## 6. 현재 알려진 한계 (규칙 아님 — 사실 기록)

- 2026-11-27 사용자 지적: 샘플 PDF(56장) 대비 생성 결과(본문 22장 + 표지)가 **페이지 수와 정보 밀도에서 밀린다.** 100점 루브릭 v1 은 이 부분을 채점하지 않는다 (`quality-rubric.md` §4). 개선 방향은 사용자 확정 대기 중이다.
